# AGENTS.md

## Commands

Only five npm scripts exist (`start`, `package`, `make`, `test:ui`, `test:parse`) — **there is no lint, typecheck, or formatter**. `test:ui` is a UI layout regression harness (see CI/release below); `test:parse` is a dependency-free unit test for `src/keyParser.js` and the renderer's log line handler (`src/renderer/js/logUtil.js`). For everything else verify by launching the app manually.
- `npm run start` — dev (electron-forge)
- Build order: `sh ./compile.sh` → `npm ci` → `npm run make`. Output: `out/make/zip/`
- `src/buildInfo.json` is generated by the forge `generateAssets` hook and is **not committed**. Always enter through `electron-forge start`/`make`; running `node src/main.js` fails on the missing file.
- `framework/bin/` is required at runtime (gitignored, not in repo). Dev resolves `../framework/bin`, packaged resolves `process.resourcesPath/framework/bin`, so `npm run start` needs `compile.sh` run first. CI rebuilds it from scratch.
- `compile.sh` prereqs (see README): Linux `apt-get install curl autoconf libtool pkg-config patchelf liblzma-dev libreadline-dev`; macOS `brew install autoconf automake libtool pkg-config`; Windows must run under MSYS2 mingw64. It deletes `framework/`, extracts vendored archives from `vendor/` (the macOS libusb-legacy binary is still downloaded from R2), and rewrites rpaths via `patchelf`/`install_name_tool` — slow, don't run casually.
- CI uses Node 24.x; `package-lock.json` is authoritative (`npm ci`).

## Tauri branch (`tauri`)

The `tauri` branch carries a Windows-only Tauri 2 rewrite of the main process. `src/renderer/` is byte-identical to `main`; the Electron files are kept only as the behavioural reference.

- `src-tauri/src/main.rs` — Tauri setup, close-guard, command registration. `src-tauri/src/commands.rs` — the `actions` map equivalent (`run_action`), all tool orchestration, dialogs and file IO. `src-tauri/src/task.rs` — spawns the C tools, `hidden_command` adds `CREATE_NO_WINDOW` so no console flashes.
- **The renderer's `electronAPI`/`darkMode` now comes from `src-tauri/src/embedded.js`**, injected into every webview via `initialization_script` (`src-tauri/src/windows.rs`). `src/preload.js` is Electron-only — editing it does **not** affect the Tauri build, and editing `embedded.js` does **not** affect Electron. Keep both in sync when adding a bridge method or event channel.
- Windows-only: `explorer.exe`/`notepad.exe` are hardcoded, `data_dir` is `%APPDATA%\NFCToolsGUI`, locale is `zh-CN` or `en` only.
- **Never run `cargo check`/`build`/`test` locally** — no Rust toolchain is installed and the Tauri build needs the MSYS2/mingw64 `compile.sh` output. Verification is the `tauri-build` workflow: push to `tauri` and poll it.
- Build order mirrors `compile.sh` → `cargo build --release`; `.github/workflows/tauri.yml` zips `nfctoolsgui.exe` + `framework/` + `dict.dic` by hand (`bundle.active=false`, no `cargo tauri build`). Release-mode `bin_dir()`/`dict_path()` resolve relative to the exe dir, so that zip layout is load-bearing.
- `src-tauri/Cargo.lock` is committed (440 packages) so CI builds are reproducible; regenerate with `cargo generate-lockfile` when adding or bumping a dependency.
- **Tauri `pump_lines` buffers newline-less tool output.** Progress lines from `libnfc-collect`/`nfc-mfdict`/`mfoc` carry no trailing newline, so `BufReader::lines()` accumulates the whole progress burst and emits it as one line — the renderer's log block can contain many `\33[2K` markers, and the live log only catches up when a newline finally arrives (unlike Electron's streaming). `logUtil.js` handles this by erasing per marker.
- **Tauri `print_log`/`print_status`/`update-events` etc. use `app.emit` (broadcast to every window)**; Electron sends those to the main window only. The auxiliary windows don't listen to them, so this is harmless today — new windows must not start listening on main-window-only channels, or prefer `emit_to("main")` instead.

## Layout

- `src/main.js` — main-process entry. `src/command.js` — the `actions` map; every UI action lands here (`renderer execAction('name', arg)` → `ipcMain 'exec-action'` → `actions[action](arg)`).
- `src/execUtils.js` — spawns the C tools from `framework/bin`. `src/windows.js` — one `BrowserWindow` per feature. `src/preload.js` — the only `electronAPI`/`darkMode` surface the renderer may use.
- `src/renderer/` — plain HTML/CSS/JS + vendored jQuery (`renderer/js/jquery-3.7.1.min.js`). No bundler, no TypeScript, no UI build step.
- `source/*` — C tool submodules (forks of `GSWXXN/*`), compiled by `compile.sh`, excluded from the asar. `dict.dic` — default key dictionary, shipped as extraResource.
- `src/status.js` is plain mutable state shared across the whole main process (device, speed, `isRunningTask`).

## Gotchas

- i18n: `src/locales/en.json` and `zh-CN.json` must stay key-identical — add a key to **both**. Main process uses `i18n("key")`; HTML uses `{{ key }}` placeholders; a missing key renders literally.
- Every renderer HTML must include `../js/i18n.js`: it rewrites `body.innerHTML` and is the only caller of `electronAPI.rendered()`. All windows are created `show: false`, so a page without it never becomes visible.
- Adding a feature touches: `actions` in `command.js`, a `create*Window` in `windows.js`, a channel in `preload.js`, HTML/JS in `renderer/`, and both locale files.
- Tool output parsing is positional string slicing, not structured parsing (`indexOf("Key found:") + 11`, `UID (NFCID1):`, `Found tag with uid `, regexes in `keyParser.js`). It silently breaks if upstream tool output changes. Two constraints that are easy to trip over and fail silently:
  - **A sector header and the key it describes can be far apart.** In the distance-attack phase the tool prints `Sector: %d, type %c, probe %d, distance %d ` with no trailing newline (`source/mfoc/src/mfoc.c:555`), then dot progress (`:568`), then the newline (`:571`) — and only then `  Found Key: %c [%012llx]` (`:602`). So the recovery sector context is **one line ahead** of the key and must be kept as cross-line state. Never read it as a line-local, and never anchor those regexes with `$`.
  - **Only the Tauri port may rely on whole lines.** `task.rs:pump_lines` uses `BufReader::lines()`, so merging stderr into the same channel is harmless — stderr lines simply fail to match. The Electron port must keep its own cross-chunk buffer, and `exec()` routes stderr to a separate handler precisely so libnfc diagnostics cannot be spliced into a half-received stdout line. Copying either half of that arrangement into the other port breaks it.
- The log textarea is capped at `LOG_DISPLAY_LIMIT` for display only; `fullLog` in `index.js` is what `save-log` sends, so a truncated display never truncates a saved log. Both go through `appendLogChunk` (`src/renderer/js/logUtil.js`), which simulates the terminal's `\33[2K` erase-current-line rewrite — progress lines are *overwritten*, never appended as separate lines. A single log block may carry several `\33[2K` markers (see the Tauri buffering gotcha below), so the handler must process every marker, not just the first.
- `exec()` in `execUtils.js` refuses to run unless a device is connected — the only exception is `nfc-list` — and `isRunningTask` allows exactly one task at a time. An action that looks broken is often just gated on device state.
- Nothing user-facing is written to the repo: `LIBNFC_SYSCONFDIR` is set to Electron's `userData`, which holds `libnfc.conf`, `keys.txt`, `temp.mfd`, `nonces.bin`, `dumpfiles/`.

## CI / release

- `.github/workflows/build.yml` builds on push to `main` (windows-only matrix, `paths-ignore` for `doc/**`, `README*`, `.github/**`) and manual `workflow_dispatch`, checking out submodules recursively.
- `.github/workflows/tauri.yml` is the `tauri`-branch build: MSYS2 → `compile.sh` → `cargo build --release` → hand-made zip → artifact → same force-move of the fixed `latest` tag/release.
- After a successful build, the workflow force-updates the fixed `latest` tag to the build commit, deletes the previous `latest` release (tag kept), and re-creates it uploading `upload/*.zip` directly as release assets (no nested zips), marked as the latest release. Manual dispatches publish too.
- `test/ui` (harness at `test/ui/runner.js`, npm script `test:ui`) is a UI layout regression check run by the `ui` job in `.github/workflows/ui.yml`. It drives each HTML page with the real `preload.js` against a stubbed IPC main (`test/ui/main.js`) and asserts element geometry. Runs without `framework/bin/` or an NFC device; Linux needs `xvfb-run` plus GTK/NSS/asound CJK-font deps (see the CI step for the exact list). Looping languages: `UI_LANGS="zh-CN,en" npm run test:ui` (default).
- `test/parse/keyParser.test.js` (npm script `test:parse`) guards the sector/key output parser: its core assertion is **chunk invariance** — stdout arrives in arbitrary blocks, so the parse result must be byte-identical to a single-chunk parse. Section 6 keeps the old `i/2`-from-match-index implementation as a witness that the test actually fails on it, and sections 7–10 cover the distance-attack recovery format (`Found Key: A [hex]`, whose sector header is on a *previous* line) plus the `unknown`→`known` hand-off when a recovered key leaves the pending queue. Section 11 covers the renderer's log `\33[2K` overwrite handling (`logUtil.js`), including the Tauri case where one buffered line carries many markers. Runs in both `ui.yml` and `tauri.yml`.
